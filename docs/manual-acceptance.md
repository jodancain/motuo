## 实际发现与修正

1. **大量重叠字形。** 物理第 26 页原有 788 个字形，按内容和坐标去重后为 360。全本由 410442 个字形降至 305706，去掉 104736 个重叠字形。没有全局删连续重复字符；`1000/5000/10000/15000`、`11 N·m`、工具编号 `09900–25009` 均有独立回归断言。
2. **默认按横行抽取会混排双栏。** 物理第 25 页的维修项目、物理第 222 页的机油检查与更换曾相互穿插。现在检测栏间实际空隙、区分全宽表格/提示行，保存段落坐标并按栏读取。第 201 页上方双栏与下方全宽止推轴瓦表也分别保留。
3. **目录页引用曾误认作本页印刷页。** 现在仅依据页眉确认印刷页，另支持目录罗马数字页码。物理第 15 页是 `1-i`，不能用正文中的 `0C-14` 当作本页。无印刷页号时返回 null，仍保留物理页。
4. **有真实空白和图示页。** 物理第 2、4、616 页无字形、图片或绘图对象，标记 blank。图示页不伪造说明；段落、表格、插图 bbox 均指回原页。
5. **数值的上标/单位和复杂图例仍需原图。** 如 cm³、kgf/cm² 可能由独立字形表现为换行；不自动改写这些数字。复杂矢量页超过 6000 条边时跳过网格表识别并记录 warning，正文照常保留。

## 2026-09-20 NAS 失败调查与本机重建

NAS a4 手册曾停在已提交 175 页，错误为 `PDF_EXTRACTION_FAILED:PdfminerException`；本轮 NAS 随后离线，因此尚未取得内部异常根因，不能把本地修复说成 NAS 故障已解决。

在全新 Python 3.12 环境严格安装 `worker/requirements-dev.txt`（含与 NAS 相同的 pdfplumber 0.11.7、pdfminer.six 20250506、pypdfium2 4.30.0），物理第 176 页单独与完整顺序解析均成功：印刷页 `1D-37`、724 个原始字形、移除 226 个叠印字形、native、无 warning。该页失败未在本机复现。

源码检查证实 pdfplumber 的 `Page.layout` 会将所有 `Exception` 包装成 `PdfminerException`，包括 worker 的 SIGALRM 页超时。新增最小处理：被包装的页/文档超时保留原错误类型及物理页，任务仍失败、已提交页面仍可恢复；真正原生解析失败仅对该页尝试本地 OCR，质量固定 `needs_review`，没有文本时 `method=unavailable`，不编造图表或数字。记录只保留错误类名，不包含文档内容或私密路径。API 对 OCR/needs_review 引用已有显式数值/单位复核提示，iOS 显示提示并支持跳回原页。

修改后 **21/21** worker 测试通过，包括独立临时 PostgreSQL、真实 OCR，以及包装页超时、OCR 中超时、解析失败且禁用 OCR、解析失败后真实 OCR 的四项新增回归。

原件修复前/后各重建一次，共 616 页。最终 `/tmp/motuo-manual-reference-20260920.jsonl`、`.stats.json`；耗时 126.705 秒，JSONL 与同环境修复前结果**字节完全一致**，SHA-256 `9db0f06e91fac68745abe5b3634ee7d6a2e76a32410c1c50c3223e60ed831242`。仍有 395 张表、412 个双栏区、7 次 OCR 尝试、6 页采用 OCR、3 页空白、第 551 页 needs_review；**41/41** 原文引用验收通过。正常原件没有触发新增 parser-failure 回退，此回退由带真实 OCR 的可控回归验证。

这些是本机源码与完整原件证据；补丁尚需 NAS 新镜像部署、恢复该手册、完成 616 页并跑真实 API 问答后才算 NAS 验收通过。临时参考会被系统清理，应按 CLI 从不变的原 PDF 重建，不能把 `/tmp` 当持久备份。
